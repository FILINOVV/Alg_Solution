## О проекте

Теория говорит, как растёт время работы алгоритма при увеличении объёма данных: линейно, квадратично, логарифмически. Приложение проверяет это на практике.

Для каждого алгоритма программа:

1. Запускает его на входных данных разного размера n;
2. Измеряет время работы;
3. Строит график зависимости времени от n;
4. Накладывает на график теоретическую кривую c·f(n), подобранную методом наименьших квадратов.

Если экспериментальные точки ложатся на теоретическую кривую, оценка сложности подтверждается.

## Возможности

- **Четыре раздела:** алгоритмы над векторами, умножение матриц, возведение в степень, история и сравнение экспериментов.
- **Настраиваемый эксперимент:** максимальный размер N max, шаг по n, количество прогонов.
- **Среднее время и стандартное отклонение** по всем прогонам для каждой точки.
- **Теоретическая кривая** c·f(n) с автоматическим подбором коэффициента c.
- **Хранение результатов** в локальной базе SQLite и кэширование уже выполненных замеров.
- **Сравнение экспериментов:** несколько сохранённых запусков на одном графике.
- **Экспорт графиков в PNG:** изображение всегда формируется в светлой палитре для вставки в отчёт.
- **Светлая и тёмная темы оформления:** выбор запоминается между запусками.
- **Подписи осей с единицами:** единица времени (нс, мкс, мс) подбирается автоматически.

## Исследуемые алгоритмы

### Часть I. Алгоритмы над векторами

| Алгоритм | Задача | Сложность |
|---|---|:---:|
| Постоянная функция f(v) = 1 | эталон, время не зависит от n | O(1) |
| Сумма элементов | один проход по вектору | O(n) |
| Произведение элементов | один проход по вектору | O(n) |
| Многочлен, наивное вычисление | степень x считается заново для каждого члена | O(n²) |
| Многочлен, метод Горнера | вычисление по схеме Горнера | O(n) |
| Сортировка пузырьком | обмен соседних элементов | O(n²) |
| Quick sort | разбиение относительно опорного элемента | O(n log n) |
| Timsort | сортировка вставками по блокам и попарное слияние | O(n log n) |
| Пирамидальная сортировка | сортировка на основе двоичной кучи | O(n log n) |
| Линейный поиск | индивидуальное задание, последовательный перебор | O(n) |
| Бинарный поиск | деление диапазона пополам | O(log n) |

### Часть II. Умножение матриц

| Алгоритм | Задача | Сложность |
|---|---|:---:|
| Классическое умножение | A(n×m) · B(m×n); отдельная кривая для каждого m | O(n²·m) |

### Часть IV. Возведение в степень

В этой части измеряется не время, а количество операций умножения: оно определяется точно и не зависит от шума измерений.

| Алгоритм | Идея | Сложность |
|---|---|:---:|
| Простой | n последовательных умножений | O(n) |
| Рекурсивный | xⁿ = x · xⁿ⁻¹ | O(n) |
| Быстрый (бинарный) | возведение в квадрат по двоичной записи показателя | O(log n) |

## Методика измерений

Для каждого значения n = шаг, 2·шаг, …, N max выполняется заданное число прогонов:

1. **Подготовка данных** — генерация случайного вектора длины n. Выполняется до запуска таймера и в замер не входит.
2. **Замер** — `System.Diagnostics.Stopwatch` измеряет только работу алгоритма.
3. **Повторы для быстрых алгоритмов** — алгоритмы, которые не изменяют входной массив, запускаются сериями, пока суммарное время не превысит 5 мс. Итоговое время делится на число запусков. Это нужно, потому что время одного вызова O(1) меньше разрешения таймера.
4. **Один запуск для сортировок** — сортировка изменяет массив, поэтому на каждый сгенерированный вектор выполняется ровно один запуск.
5. **Статистика** — по всем прогонам вычисляются среднее время и стандартное отклонение.

Коэффициент теоретической кривой c·f(n) подбирается методом наименьших квадратов:

$$
c = \frac{\sum_i f(n_i)\, T_i}{\sum_i f(n_i)^2}
$$

где $T_i$ — измеренное время для $n_i$, а $f(n)$ — функция из оценки сложности.

> [!TIP]
> Для корректных замеров запускайте приложение в конфигурации **Release**: в Debug оптимизации компилятора отключены и результаты содержат больше шума.

## Запуск

**Требования:** Windows 10 или 11, [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

Через IDE (JetBrains Rider или Visual Studio):

1. Клонировать репозиторий.
2. Открыть `LabApp.sln`.
3. Выбрать конфигурацию **Release** и запустить проект.

Через командную строку:

```bash
git clone https://github.com/FILINOVV/LabApp.git
cd LabApp
dotnet run -c Release --project LabApp/LabApp.csproj
```

База данных `results_v2.db` создаётся автоматически рядом с исполняемым файлом при первом запуске.
